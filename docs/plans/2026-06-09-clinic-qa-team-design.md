# 醫美診所套件 QA 團隊迭代測試設計

## 團隊組成（5 位專家）

| # | 角色 | 職責 | 執行方式 |
|---|------|------|----------|
| 1 | Odoo 流程測試專家 | 模擬前台/醫師/管理者日常操作，走完核心流程，記錄異常 | 並行 |
| 2 | 程式碼修復專家 | 收到彙整問題後修改程式碼 | 序列 |
| 3 | 錯誤解析專家 | 分析根因、排定優先級 | 並行 |
| 4 | 醫美商業流程專家 | 從診所營運角度審視流程合理性 | 並行 |
| 5 | 最終驗收評審 | 每輪結束後獨立評分 pass/fail | 每輪結尾 |

## 迭代流程

```
Phase 1：並行測試（專家 1, 3, 4 同時）
Phase 2：彙整問題清單
Phase 3：程式碼修復（專家 2 序列修改）
Phase 4：驗收評審（專家 5 獨立評分）
  PASS → 結案
  FAIL → 提高門檻，進入下一輪
```

## 階段門檻遞進

| 輪次 | 門檻 | 測試範圍 |
|------|------|----------|
| 第 1 輪 | 核心流程走得通，無報錯 | 掛號→看診→寫病歷→簽核→查歷史 |
| 第 2 輪 | 流程正確 + 資料一致 | 加入：欄位驗證、計算欄位、序號正確性 |
| 第 3 輪 | 全部正確 + 權限合規 | 加入：角色權限、記錄規則、稽核日誌 |
| 第 4 輪+ | 零缺陷 | 回歸測試全部通過，商業邏輯零瑕疵 |

## 測試方法

- 使用 JSON-RPC 直接對 Odoo API 操作（localhost:9103）
- 模擬真實角色（前台 Medical User、醫師 Physician、管理者 Admin）
- 核心流程：建立病患 → 建立病歷 → 填寫 SOAP → 簽核 → 查歷史病歷
- 由淺入深：先確保基本功能，再逐輪加嚴標準

## 執行策略

- 並行式：測試、解析、商業審查同時進行
- 修復後必須重新驗證
- 無輪次上限，直到過關
